# 2026-09-17 代码汇总与评估

这轮结果支持“routing 有用，其中局部 correction 很重要”，但还不支持
“外部 per-head predictor 学到了稳定、通用的语义控制接口”。普通语言建模、
上下文取词和部分固定 SAE 方向有正结果；GSM8K 生成没有测到成对提升。

本文随最后几组评估完成更新。完整数值、区间和运行设置在
[评估总报告](README.md)，历史差异在 [PR 与代码审计](../../PROJECT_SYNC_2026-09-17.md)。

## 代码和架构

已汇总本地未推送工作、GitHub 上合并的两个 PR，以及 Delta
`/projects/bfqt/users/yurenh2/ml-projects/DAGFormer` 的 59 个修改或新增文件。
Delta 的这批 September 3–13 工作已恢复到 Git，原目录保留。

当前模型由外部 causal encoder 预测每层、每头的 Q/K/V 混合系数，另有各层
hidden state 驱动的 correction MLP；R 系数在头之间共享。系数是有符号的连续值。
当前实现没有通过离散开关跳过计算。300M 配置共 3,773 个 routing 坐标：
3,234 条 hyperconnection 和 539 条 sequential path。

75M、150M、300M 指 backbone 档位。Full DAGFormer 的实际参数分别为
105.66M、182.56M、336.45M，比对应 baseline 大。此次主比较核实了训练 token
数相同：1.573B、3.146B、4.719B；没有把它称为等参数或等 FLOPs 比较。

## 普通 eval

三个档位的 baseline/DAGFormer 都完成了 14 项 likelihood/选择题评估，以及
GSM8K 全量 1,319 题生成。300M 主比较双方都用 step 9000。

| 300M 指标 | Baseline | DAGFormer | 成对变化 |
|---|---:|---:|---:|
| WikiText BPB，越低越好 | 1.0714 | 1.0225 | 降低 0.0489 |
| LAMBADA accuracy | 25.54% | 30.18% | +4.64 个百分点 |
| HellaSwag normalized accuracy | 29.81% | 31.45% | +1.63 个百分点 |
| SciQ accuracy | 63.90% | 69.80% | +5.90 个百分点 |
| GSM8K 条件 gold-answer BPB | 1.6870 | 1.5684 | 降低 0.1186 |
| GSM8K 生成 numeric match | 1.59% | 1.52% | -0.08 个百分点，区间包含 0 |

前三个档位的 GSM8K 生成成对差异都没有检出提升；上述六个 checkpoint 的
严格 `####` 格式命中均为 0。
输出中重复和无关文字很多，数字碰巧一致也可能被 flexible extraction 算对。
给定正确的前文后，gold answer 更可能，并不表示模型能自行写出正确解答。
300M baseline 的 200 题 cache/no-cache 对照，正确题目完全一致，重复问题仍在。

标准 CommonsenseQA 存在几乎总选 A 的问题；改为直接比较候选答案文本后，
未出现跨三个档位稳定的提升。BoolQ 的相对提升也仍低于恒答 yes 的基线。
因此不把所有任务的正差值合并成“推理能力全面提升”。

最新 step 10500 的普通 14 项评估已完成：WikiText 从 1.02248 降到 1.01830，
12 个 accuracy 指标与 step 9000 的成对差异区间均含 0。它多训练了约 0.787B
tokens，适合看继续训练的变化，不能替代等预算主比较。
它的全量 GSM8K 生成也已完成：numeric match 从 20/1,319 升到 26/1,319，
即 1.52% → 1.97%，差异区间仍包含 0。3 个严格格式命中的输出都有错误算式
或无关推导；[原文示例](gsm8k_latest/generation_examples.md) 保留了这三例。
作为未配对参考的 600M baseline 也完成全量生成：numeric match 25/1,319
（1.90%），严格格式命中 1/1,319（0.08%）。

## 可解释性结果

外部 predictor 的内容变化影响很小，但它学到的静态、位置相关连线有用。
300M 在独立 WikiText test windows 上，把 predictor 换成 train windows
校准的位置均值表，NLL 只增加 0.00061；将 correction 置零则增加 1.7493。
FP32 和相邻窗口 block bootstrap 保留这个结论。这里是固定权重干预，
不代表训练过程可以随意删除任一模块，也不把两个 channel 当作独立贡献相加。

已有的五个 150M 简化架构 checkpoint 也完成普通 eval。Static+corr 和 lite
以约 153–155M 参数，取得接近或略优于 full 182.56M 的部分指标；纯 static、
纯 position-table 则明显弱一些。这使“保留局部 correction，简化外部 predictor”
成为有实测依据的下一步候选。目前每种只有一个训练实例。
其中 static+corr 只比 dense 多 855,183 个参数（0.56%），WikiText BPB
从 1.1959 降到 1.1489，LAMBADA 从 15.62% 升到 21.48%。因此这部分收益
不需要 full 模型额外的约 30M encoder 参数；尚不能据此推断所有规模都如此。

固定的十条 context-fidelity 边在新样本上能提高部分上下文属性输出。
在第三组 1,024 个新 items 的 narrative/deceptive 生成中，both-channel
gamma 1.25 把正确属性字面命中从 45.90% 提到 49.12%；dialogue 也有提升。
但许多失败是遗漏属性，例如只说 ring、没说 iron，不是输出错误的备选属性。
全 61,440 条 continuation 中没有发现列出的错误备选值。因此这是上下文属性
提取/保留证据，不能直接命名为“诚实/说谎开关”。

更明确的属性问答没有延续这项收益。在第 4 批 1,024 个 item 上，both 编辑
把 deceptive 条件的正确首个属性命中从 81.25% 降到 78.22%，遗漏率从
11.23% 升到 16.41%。它同时减少了继续说出其他备选属性的情况，说明不同
指标会呈现不同取舍，不能用后一个计数替换主要指标。按相同提示分组后，
负向结果仍在；固定方向尚不能稳定迁移到不同内容和问法。

这里“新 item”按事实、提问、人物和对话对象组合去重，未要求每个事实句子
都没见过。Neutral QA 不显示对话对象，因而会有相同提示；新问答组实际有
830 个不同 neutral 提示、1,024 个不同 deceptive 提示。报告给出了相应的
分组 bootstrap 和原始输出。

同一个固定编辑还把普通 LAMBADA 从 30.18% 提到 32.51%，但 WikiText BPB
变差 0.0043。事后分组显示，净增加的 120 道正确中，114 道来自答案 token
已经出现在上下文的题目。这符合上下文复用的解释；分组本身不能证明因果中介。
两个相同局部编辑幅度的随机头对照分别是 29.52% 和 31.11%，选定方向都更高；
但选定方向的 WikiText 代价也明显更高。它有定向效果，尚不能称为等能力代价
下最优的编辑。

历史固定 SAE 方向在新 WikiText 上，8 个中有 3 个重现了双向 target-token
loss 效果：3560、7068、4222。另 4 个的 dose-span 区间包含 0，7019 在新语料
没有对应 token，无法判断。Kinship 方向 3583 没有稳定复现。token 集合混有
空白、标点和词片段，不能把 feature 名称直接当成干净的语义概念。
例如 7068 的 4,134 个目标 token 中，4,032 个是空白片段；3583 所谓 kinship
集合的 246 次命中里，186 次是 `two`，并非亲属词。

75M、150M 在新的重复序列任务上比 dense baseline 有明确 copy accuracy
优势；300M 在 period 64 有小幅优势，period 128、256 的差异不确定。
这是 teacher-forced 合成重复任务，不等同于自然文本推理。

## 两个 PR 为什么与原分析不同

[PR #1](https://github.com/AI-Interpretability-Illinois/dagformer/pull/1)
主要测普通 benchmark。它的选择题 win/loss/tie 应为 14/5/2；原文混入了
likelihood 和生成指标。WikiText 的旧数值差异还涉及 dense step 9000 和
12000 混用。此次已统一主比较 checkpoint，并把 GSM8K gold-answer likelihood
与生成正确率拆开。

[PR #2](https://github.com/AI-Interpretability-Illinois/dagformer/pull/2)
测的是“指令对比找方向，再编辑该方向”；原分析的 copy heads、十条 context
边和 SAE 是不同选法、不同 endpoint。PR 还只搜 hyperconnections，遗漏了
原十条边里的三条 sequential paths。两者结果可以同时成立。

PR #2 的自动 NULL 标签用了 edited score 的原始 SEM，不是成对变化的
不确定性；stream arms 又没有测 NLL。新评估按内容 item 汇总 paraphrases，
补上成对区间、32 个新内容和能力代价。小剂量 correction Q/V 的确有约为
指令差距 1–2% 的分数变化，但主要是 prose likelihood 降低，且不稳定优于
所有对照，不能据此宣称语义 steering 成功。原数值文件保留，解释修订可追踪。
