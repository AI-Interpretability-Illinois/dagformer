Current architecture
- The dense LM is wrapped by a FourWay routing mechanism.
- For layer 0, the model is standard attention.
- For layer l > 0, each token predicts routing weights over previous layer outputs:
  - alpha_q: per-token, per-head, over source layers
  - alpha_k: per-token, per-head, over source layers
  - alpha_v: per-token, per-head, over source layers
  - alpha_r: per-token, shared across heads, over source layers
- Mechanically, each previous layer output is first projected through normal Q/K/V projections, then mixed using alpha_q / alpha_k / alpha_v. Residual carrier R is mixed separately using alpha_r.
- The output is roughly R + attention_out + MLP_out.
- Identity init is exact: routing output heads start at zero weights, with biases initialized so the routing is exactly identity at step 0. So the model is mathematically equivalent to the dense transformer at initialization.
- There is also a “fourway_corrected” variant that adds local correction MLPs inside the routed model, on top of the external predictor.

Predictor
- The main external predictor is currently an independent causal encoder:
  - separate token embedding + position embedding
  - 2-layer transformer encoder
  - encoder dim 256
  - hidden dim 512 trunk
  - outputs all alpha_q / alpha_k / alpha_v / alpha_r for every token and every layer
- So this predictor is input-conditioned and outputs a large amount of continuous routing information.

Main empirical facts
- Dense 300M baseline eval NLL: 3.8459
- Best fourway_corrected_joint_causal eval NLL: 5.4924
- Pure FourWay long-train variant reached 5.3702 at step 6000
- So FourWay is substantially worse than dense on eval, even though it can drive train NLL much lower.

The important phenomenon
- The model clearly overfits / generalizes badly.
- It is not an eval bug.
- It is not just train/eval mode mismatch.
- It is not that routing does nothing.
- Forced-identity eval on the same trained checkpoint gave:
  - full FourWay: 5.4924
  - identity routing + corrections on: 5.9662
  - predictor only, no corrections: 6.3161
  - identity routing, no corrections: 7.0774
- So routing is genuinely useful, but it learns a solution with poor generalization.
- Also, local corrections contribute more than the external predictor:
  - corrections improve more than predictor-only routing does
  - this suggests local dynamic capacity may be a major source of overfitting
